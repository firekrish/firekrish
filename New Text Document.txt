Discussion Summary
Eric explained that Service Design Packages (SDPs) associated with applications are automatically scanned to identify gaps or missing information. The results of these scans are provided through Excel spreadsheets.

The email shared with the team contains links to two spreadsheets:

FCB SDP scan report
SVB SDP scan report
Applications appear in the appropriate spreadsheet depending on whether they belong to the FCB or SVB environment.

The spreadsheet includes the application ID, SDP link, overall completion percentage, and details about gaps identified during the scan.

Initially, access to one of the spreadsheets was unavailable. An access request was submitted, and Eric also requested access on behalf of the team member.

SDP Compliance Threshold
Eric confirmed that the current required SDP compliance threshold is 90%.

For example, Application ID 10302 was reviewed and showed a score of 93.22%.

Since the application is above the 90% threshold, remediation is not currently required.

However, applications can still be improved toward 100% compliance if desired.

The general rule confirmed during the meeting is:

90% or higher: No mandatory remediation is currently required.
Below 90%: The SDP must be reviewed and remediated.
100%: No identified remediation is required based on the scan.
How to Review an Application
Once access to the spreadsheet is available, the team should identify all applications owned by the team.

Applications can be searched using:

Application ID
Application owner
Other identifying information available in the spreadsheet
For each application, the spreadsheet provides a link to the associated SDP document.

The scan results identify the specific sections of the SDP that contain gaps.

Examples of SDP Scan Issues
Eric demonstrated several common issues that may appear in the scan report.

Examples include:

Required checkboxes are missing.
A required checkbox exists but has not been selected.
Required fields in a table are blank.
A required section is missing.
A section exists but contains no information.
A required prompt has not been answered.
A required table is missing.
A required diagram is missing.
A section header was modified, preventing the scanner from recognizing the section.
The SDP template structure was changed from the expected format.
One example involved the Recovery Objective section. The scanner expected checkboxes within the appropriate column, but the template had apparently been modified and the expected checkboxes were no longer present.

To resolve such an issue, the correct checkbox structure would need to be restored and the appropriate option selected.

Remediation Process for Applications Below 90%
Eric confirmed the following process for any application whose SDP score is below 90%:

Open the Excel scan report.
Locate the application.
Review the gaps identified in the scan report.
Click the SDP link associated with the application.
Download a copy of the current SDP Word document.
Update the SDP based on the gaps identified in the scan report.
Ensure all required sections, fields, tables, checkboxes, diagrams, and responses are completed.
Save the corrected SDP.
Upload the corrected document back to the SDP repository.
Use the same file name so the updated document overwrites/replaces the previous version.
